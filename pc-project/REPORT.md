# PC Configurator — звіт

## 1. Ідея проєкту

PC Configurator — вебзастосунок магазину готових ігрових та робочих
комп'ютерів. Користувач переглядає каталог, фільтрує збірки за процесором,
відеокартою та ціною, відкриває детальну сторінку і змінює обсяг оперативної
пам'яті або додаткове сховище. Загальна ціна перераховується одразу після
зміни опції.

Основний користувацький сценарій:

1. Відкрити головну сторінку.
2. Перейти до каталогу готових збірок.
3. Застосувати фільтри або обрати конкретний ПК.
4. Налаштувати комплектуючі.
5. Перевірити підсумкову ціну.

## 2. Архітектура та структура проєкту

Застосунок реалізовано як React SPA на Vite. Маршрутизація виконується через
`react-router-dom`, дані каталогів зберігаються в окремому модулі, а UI
розділений на повторно використовувані компоненти та сторінки.

```text
vite-project/
├── src/
│   ├── components/
│   │   ├── Footer.jsx
│   │   ├── Header.jsx
│   │   ├── Layout.jsx
│   │   └── ProductCard.jsx
│   ├── data/
│   │   └── products.js
│   ├── pages/
│   │   ├── CatalogPage.jsx
│   │   ├── HomePage.jsx
│   │   └── ProductPage.jsx
│   ├── App.jsx
│   ├── App.css
│   └── main.jsx
├── cypress/
│   ├── component/
│   └── e2e/
├── public/images/
├── .husky/pre-commit
├── eslint.config.js
├── cypress.config.js
├── vite.config.js
└── package.json
```

`Layout` забезпечує спільні Header/Footer, `CatalogPage` відповідає за
фільтрацію, `ProductPage` — за конфігурацію та обчислення ціни, а
`ProductCard` використовується для відображення елементів каталогу.

## 3. Обґрунтування рішення

React обрано через компонентну модель: картка товару, навігація, layout та
форма конфігуратора можуть повторно використовуватися без дублювання HTML.
Vite забезпечує швидкий dev-сервер і просту production-збірку. Для цього
проєкту достатньо локального стану React (`useState`) і статичного модуля
даних, тому додавання глобального state manager або backend було б
невиправданим у межах навчальної роботи.

Маршрути `/`, `/catalog` і `/products/:productId` розділяють основні
користувацькі сценарії та дозволяють тестувати їх незалежно.

## 4. Технологічний стек

- React 19;
- Vite 8;
- React Router;
- JavaScript/JSX;
- ESLint;
- Prettier;
- Husky + lint-staged;
- Cypress component tests;
- Cypress end-to-end tests;
- GitHub Actions для CI.

## 5. Якість і тестування

Перед комітом Husky запускає `lint-staged`, який форматує та перевіряє змінені
файли. Cypress component tests перевіряють фільтрацію каталогу та перерахунок
ціни. Cypress E2E тест проходить повний сценарій від головної сторінки до
налаштування конкретної збірки. GitHub Actions запускає lint, Prettier,
component/E2E тести та build-процес у pull request.

## 6. Висновки

У результаті створено React-застосунок із реальним каталогом ПК,
маршрутизацією, фільтрами, конфігуратором і динамічною ціною. Проєкт має
узгоджений інструментальний стек, автоматичні перевірки якості та тести
основних користувацьких сценаріїв. Архітектура залишає можливість у майбутньому
підключити API або базу даних без зміни структури UI-компонентів.
